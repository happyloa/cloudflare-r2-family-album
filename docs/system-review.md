# 系統檢查紀錄

檢查日期：2026-10-04。存取方式依使用者確認，維持公開瀏覽、密碼管理。

目前的 Next.js／Vinext、輕量 React 元件與 R2 S3 API 架構足以支援家庭相簿的現有功能。本次修復了資料操作、管理狀態、分頁搜尋與手機操作的具體問題，並加入可重跑的驗證。這份紀錄說明已驗證的範圍；正式環境與大量資料的表現仍需另行確認。

## 修復內容

| 項目 | 調整與效果 |
| --- | --- |
| 搬移與重新命名 | 確認 CopyObject 的 XML 結果後才刪除來源，避免 HTTP 200 內含錯誤時誤刪原檔；新增回滾與來源保留的回歸測試。這種回應情況見 [AWS CopyObject 文件](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)。 |
| 資料夾層數 | 搬移前檢查整個子樹，超過兩層時拒絕寫入；檔案可移到第二層資料夾，第二層不再顯示可用的建立資料夾操作。 |
| 同名上傳 | 檔名加入 UUID，避免同時間、同名的不同請求互相覆蓋；移除上傳前的整個資料夾掃描。顯示與搜尋時使用原始檔名。 |
| 管理驗證 | 使用 runtime 的常數時間比較；修復登入後第一次操作讀到舊 token、登出後遲到驗證重新啟用管理模式的問題。401 會清除過期狀態，服務故障與錯誤密碼有不同提示。 |
| 請求限制 | 管理 JSON 上限 256 KiB、批次移動／刪除上限 200 個項目；拒絕空名稱與只含句點的路徑片段。記憶體中的失敗 IP 紀錄最多保留 4096 筆並清理到期紀錄。 |
| 上傳 | 保留 GIF、WebP 等格式的動畫，只嘗試壓縮 JPEG；壓縮後更大時保留原檔，釋放 ImageBitmap，加入上傳逾時處理。伺服器確認的結果包含大小與修改時間。 |
| 刪除與容量 | 保留完整六秒復原時間，阻止第二批操作提前結束第一批的復原時間；離開頁面會取消未送出的刪除。背景刷新不再把待刪項目重新顯示，實際刪除成功後刷新容量。 |
| 搜尋與分頁 | 搜尋控制移到資料夾上方，搜尋時展開符合條件的年份群組；搜尋／類型篩選會補載目前資料夾的剩餘分頁。失敗會停止自動重試，重複 cursor 會顯示錯誤。排序提示明確說明尚未載入的項目。 |
| 桌面與手機 | 觸控裝置可直接多選，修復操作選單被延遲的捲動事件關閉。預覽焦點不再隨切換重設，保留影片控制的方向鍵功能，對話框支援窄螢幕與橫向捲動。超長標題顯示兩行，頁碼保持同一行。 |
| 預覽與空畫面 | 圖片／影片失敗提供提示與重試入口；影片縮圖增加播放提示。空相簿說明符合公開瀏覽與管理模式的實際操作。 |
| 首頁字型 | 移除 `@fontsource/noto-sans-tc`，使用裝置既有的繁中字型與系統字型。桌面與手機的隔離首頁測試均確認沒有額外字型請求；先前的子集版本仍需下載 847,304 bytes。字型呈現會隨作業系統略有差異，尚無正式網站 Core Web Vitals 結果。 |

最終本機驗證結果：

- `npm ci`：乾淨安裝成功，沒有 npm 安裝警告。
- `npm audit`：0 個漏洞；`npm outdated`：所有直接依賴皆無較新版本，包含新增的 Playwright 與 jsdom 30.1.2。
- `npm run verify`：Vinext 相容性、TypeScript、15 個測試檔的 44 項回歸測試、Next.js 正式建置與 Workers 正式建置通過。
- Next.js 與建置後的 Workers 各通過 19 項瀏覽器測試；各略過 1 項僅供桌面的拖曳測試，手機移動由觸控多選與移動視窗驗證。
- 建置後的 Worker 以 Wrangler 部署 dry-run 通過。GitHub Verify 工作流程已加入兩種 runtime 的瀏覽器測試，本次紀錄不代表遠端 CI 已執行。

## 程式碼精簡與套件取捨

同日另檢查了功能程式碼與依賴用途，完成以下精簡：

- 單筆、批次與拖曳移動共用一個前端處理流程，重新命名的狀態與對話框只保留實際需要的欄位。
- 共用對話框的焦點、Escape 與捲動鎖定，避免多個對話框各自處理；重疊時只由最上層接收鍵盤操作。
- 合併移動目的地的首批與分頁載入，保留取消過期請求，補上逾時、重複 cursor 與失敗重試。分頁失敗時保留已載入的目的地。
- 移除操作後固定延遲 1.5 秒的刷新，成功後直接刷新；重新命名不再重複刷新。S3 清單查詢的強一致性見 [Cloudflare R2 文件](https://developers.cloudflare.com/r2/reference/consistency/)，公開媒體網域的快取仍需另外考慮。
- 檔案重新命名與移動共用複製／刪除來源的程式碼，保留既有衝突處理、結果確認與錯誤保護。
- 刪除只轉送匯出的 `sanitize.ts`，直接引用共用路徑函式；清理不必要的型別、傳入參數與分支。

功能程式碼（`app`、`components`、`lib`）淨減少 424 行，刪除一個轉送匯出的檔案。直接依賴由 27 個減為 26 個，其中 18 個是開發工具。剩餘依賴的用途如下：

| 用途 | 套件與保留原因 |
| --- | --- |
| 框架與渲染 | `next`、`react`、`react-dom`、`react-server-dom-webpack`、`vinext`：目前的 App Router、Next.js 開發流程與 Workers 的 RSC 建置需要。 |
| R2 | `aws4fetch`、`fast-xml-parser`：S3 請求簽章與 XML 回應解析。 |
| 部署 | `@vinext/cloudflare`、`wrangler`、`@cloudflare/vite-plugin`：既有 Workers 建置與部署整合。 |

## 保留的限制與後續建議

公開清單與媒體網址是既定需求；`robots` 設定不能控制誰可以存取。正式 R2 寫入、正式管理密碼、公開媒體網域與部署後的瀏覽器操作尚未驗證。本次使用隔離資料與本機 Worker，沒有修改正式相簿。

資料夾與批次操作包含多次 S3 請求，不具備跨物件交易保證。失敗前可能已有部分項目完成；介面會重新整理清單，重試前應先確認結果。若未來資料量明顯增加，應測量遞迴清單與搬移的耗時，再評估背景作業；目前未新增 Cloudflare 資源。

驗證失敗次數與容量快取保存在各 Worker isolate 的記憶體，屬於盡力而為的限制與快取。介面的 10 GB 是可繼續上傳的提醒，沒有伺服器硬性配額，不是零費用保證。HEIC／HEIF、QuickTime 的播放能力依瀏覽器而異，目前提供失敗提示，沒有新增轉檔服務。

Workers 建置仍會出現 Vinext／Vite 的 `INEFFECTIVE_DYNAMIC_IMPORT`、bundler `debugName` 提示與路由無法靜態分類的提示；建置成功，這些與 npm 安裝警告不同。本次沒有修改上游套件來隱藏訊息。

專案仍使用 `wrangler.jsonc`，因此開發、建置與部署保留 Wrangler。建議後續另做一次完整的 `cf` 遷移：先 `cf migrate --dry-run`，確認 Vinext 整合、bindings、資源 ID、routes、triggers、scripts 與 CI，再完成配置遷移及部署驗證。

本次使用的 Workers skill 已同步確認的官方來源，humanizer 與 Wrangler skill 已比對上游內容。受管理的 computer-use 插件未提供可用的更新機制，無法確認其最新版；瀏覽器工具無可用連線，已依使用者授權改用 Playwright。
